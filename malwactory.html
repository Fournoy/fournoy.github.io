Malwactory project

This project aim to help and automate the development and the test of malwares. The main objective is to build a tool that can be used in you're development environnement, reliable and with multiple functionnality.

Context

In order to understand weapons from malicious actor, this is important to understand processus, technics and the construction of these weapons. Malware, payloads, worm and so on are built using different technics, technologie for different context and attack purposes. To understand well we need to train ourself to building, playing and analysing weapons like malware. This can be done by creating these different weapons for exemple.

Problem

During the construction of a malware, obfuscation, compilation, junk code integration can be repetitive, especially during the test phase, we talking about a sparse environnment. Also, analysis may compromise the malware, especially if using VirusTotal or other analysis online tools, because of the creation of artifact (hash, imphash, JA3/JA3S, network communication an so on...), this is very important to make test in a well controled network or DevOps environment.

Solution

This project aim to automatized some aspects of malware devlopment processeses. Obfuscation, complementary integration code (like syscall), junk-code integration, compilation (with LLVM-obfuscator), anti-analysis technics, shellcode malware generation and so on... We will use for that several tools concentrating into one. Theses tools will make all the hard works and developper will only focus on functionnality of their malware.

How Malwactory is construct

Malwactory have three differents sections. Theses three sections aims to do they own work and can be used easily with the CLI. They are categorise depending on there purposes. Let's introduce "Malwadd", "Malwobf" and "Malwonder".

Malwadd

Malwadd will add functionnality function like anti-analysis, will generate shellcode malware and will be improve for more functionnality with time. Let's talk a bit about the function integrator.

Function integration are very hard (for me) so to avoid hours of lecture each time i want to used them correclty, or to avoid the copy-past from previous project or internet, we integrate a process that will replace some intermediate representation in a complete function.
Using a python script and regex, the first task for the pre-commit will investigate files in "/dev" repository and search for "intermediate representation" (key words). For exemple ,you want to use an Anti-analysis function, you will use Antianalysis() intermediate representation directly in the code. The script will replace the "symbole" by the entire function made to use it directly. the
Function integration have a sort of mutex to avoid double treatment, commit fails and to tell to the developper that this file have been treat with the script. The mutex are easy to spot, they are all references about Dune (Franck Herbert novel) lore.

The shellcode generator aim to create a complete shellcode malware from a C++ file made by the developper. You have three different options using the shellcode generator. You can create the payloads and the loader. You can create only the loader or you can create only the shellcode. Soon, a new option will be add. This option aim to generate the entire malware AND the loader. The purpose is to generate a shellcode malware that can be used easily for a poc.

Of course, the use of the shellcode malware will depend on the user. You can create the malware without the shellcode in it, or with the shellcode in it.

Shellcode loader tutorial with Malwactory :

First of all, we need to have our payloads written in C++ or C. Malwactory have two scripts that aim to create a shellcode, one for the C++ and the other one of C. Our code here is in C++, but if yours are not, you just will need to change one thing in you're command. The second step will be to create our shellcode. I use Donut for that. Let's create our shellcode !

For people using a C written payload, use this command : python malwadd.py --shellcode-c-windows -c <"file_path"> --flag 2

Yo have now a .bin and .exe file. You can delete the .exe file, it will not be usefull. Let's focuse on our .bin file. In it, we can extract the shellcode. Use this command in the terminal : python malwadd.py --extract-shellcode --file-path .\dev\payloads.bin

After the command, a file named shellcode.txt will appear in you're /dev directory, just copy paste the entire line into you're loader. In my loader (using one of the function available in Malwactory), i will need to paste the shellcode directly into the code. But some other loader will not work this way, like, the loader will extract directly the shellcode from a .bin file. Make sure to use correclty the .bin file !

Now, our loader is ready (i will not explicitly talk about the creation of the loader but keep in mind that it's one of the function available into the database of method.) Now, we need to create our loader.exe, for that we will use a simple command : python malwadd.py --shellcode-cpp-windows --loader .\dev\<'loader_file'> --flag 3 Using this command, you will have you're loader !

Now, we run our loader.exe

Malwobf

Malwobf will be used in order to obfuscate the malware. Changing variable names, adding junk-code and using LLVM-Obfuscator (not yet) the purpose of this is to make the malware hard to understand statically and dynamically.

Malwonder

The purposes of malwonder is to analyse the code in order to securise the program. Seecking for Windows APPI function, code analysis in order to prevent from memory problem, hash analysis and so on are used to prevent problems for the malware.

IAT analysis

Here we will search for externals functions list (API) call by the programm to understand what the program will use. After, we going to compare the list with a black list with banned API. You can see below the .yaml code to understand more. We will trigger only if we find a black listed API.

Entropy analysis

The entropy analysis will analyse the randomness of data into a file. The result is between a 0 and 8, highest is the number, more entropy we have, so more randomness. Analysis tools will trigger file with a high number of entropy. So it's important to test this. With entropy we can also know if a payload is wrapped.

URL checker

Here come an interesting test (more because of how it work). The purpose of this test is to know if URl in coded files is generate or not. For that, we using a probabilistic automata harded coded in the framework. The Job will use the script and test all the URl found in every coded files to know if they are generated or not. This test aim to improve the stealthiness of loding phase, data extraction phase and for fileless-malware.

How the probabilistic automata work

The probabilistic automata will first traine itself with a data bank of know and legitime url. This is the training data set. For each url, he will calculate the link between a letter and another. For each new, or know link, it will add a number. At the end, we have a percentage and it will trigger or not the url. You can see below an exemple for the word "google". 


Initial state: total_score = 0.0
1. Pair (G, O)
├─ 'G' in matrix?
│   ├─ YES: 'O' follows 'G'?
│   │   ├─ YES ──► total_score += 0.15 (prob G->O)
│   │   └─ NO ───► total_score -= 10.0 (transition penalty)
│   └─ NO ───────► total_score -= 10.0 (unknown letter penalty)

2. Pair (O, O)
├─ 'O' in matrix?
│   ├─ YES: 'O' follows 'O'?
│   │   ├─ YES ──► total_score += 0.05 (prob O->O)
│   │   └─ NO ───► total_score -= 10.0
│   └─ NO ───────► total_score -= 10.0

3. Pair (O, G)
├─ 'O' in matrix?
│   ├─ YES: 'G' follows 'O'?
│   │   ├─ YES ──► total_score += 0.02 (prob O->G)
│   │   └─ NO ───► total_score -= 10.0
│   └─ NO ───────► total_score -= 10.0

4. Pair (G, L)
├─ 'G' in matrix?
│   ├─ YES: 'L' follows 'G'?
│   │   ├─ YES ──► total_score += 0.08 (prob G->L)
│   │   └─ NO ───► total_score -= 10.0
│   └─ NO ───────► total_score -= 10.0

5. Pair (L, E)
├─ 'L' in matrix?
│   ├─ YES: 'E' follows 'L'?
│   │   ├─ YES ──► total_score += 0.20 (prob L->E)
│   │   └─ NO ───► total_score -= 10.0
│   └─ NO ───────► total_score -= 10.0

After a million of test like this, we have our weight for each path. The script will do the same test, regardless the weight, in URLs found by the script. If the value, at the end of the test, is below 30, the url will be automatically suspected as malicious because of the generated pattern
